# Recruiting Context Reference

## Purpose

Use this reference to make LinkedIn posts more effective for technical recruiting.

The goal is not to beg for opportunities.

The goal is to make the user's work legible to recruiters, hiring managers, and senior engineers.

## What recruiters should quickly understand

A good LinkedIn post should make these signals visible:

* What the user built.
* What problem the project solved.
* What stack or technical area was involved.
* What level of ownership the user had.
* What trade-offs the user considered.
* What the user learned.
* Why the work is relevant to engineering roles.

## Strong recruiter signals

Emphasize these when supported by the article:

* End-to-end project execution.
* Backend development.
* Frontend development.
* System design.
* API design.
* Database modeling.
* Testing.
* CI/CD.
* Debugging.
* Refactoring.
* Observability.
* AI-assisted development.
* Technical writing.
* Product thinking.
* Architecture decisions.
* Performance considerations.
* Security considerations.
* Developer experience.

## Weak recruiter signals

Avoid relying only on:

* "I am passionate."
* "I love technology."
* "I worked hard."
* "I learned a lot."
* "This was amazing."
* "AI is the future."

These are too generic.

Replace them with concrete evidence.

## Better framing

Weak:

```txt
I am passionate about AI and backend development.
```

Better:

```txt
This project helped me connect AI-assisted development with backend architecture, repository context, and repeatable engineering workflows.
```

Weak:

```txt
I built a cool project.
```

Better:

```txt
I built a small backend generation tool to explore how Codex sessions can become useful engineering context instead of disposable chat history.
```

Weak:

```txt
I learned a lot about system design.
```

Better:

```txt
The main system design lesson was that the hard part was not generating files, but defining boundaries, constraints, and feedback loops that made generation reliable.
```

## Recruiting tone

The tone should be:

* Confident.
* Specific.
* Technical.
* Clear.
* Professional.
* Not desperate.
* Not arrogant.

The post should create the impression:

"This person can build, reason, document, and communicate."

## What to avoid

Do not write:

* "I am looking for a job" unless the user explicitly asks.
* "Recruiters, contact me."
* "Please help me find an opportunity."
* "Open to work" unless the user asks.
* Inflated seniority claims.
* Unsupported impact claims.
* Fake production metrics.
* Generic career advice.

## Preferred ending

Use endings like:

```txt
I wrote the full breakdown here:
```

```txt
I go deeper into the architecture and trade-offs in the article.
```

```txt
This was a useful exercise in turning an idea into a technical artifact that can be explained, reviewed, and improved.
```
