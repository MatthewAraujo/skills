# LinkedIn Post Patterns

## Pattern 1: Project launch

Use when the user is announcing a project or article.

```txt
I published a technical breakdown of <project>.

The project started with <motivation>.

In the article, I cover:
- <point>
- <point>
- <point>

The main lesson was <lesson>.

<link>
```

## Pattern 2: Lessons learned

Use when the article is mainly reflective.

```txt
I built <project> and the biggest lesson was not what I expected.

At first, I thought the hard part would be <assumption>.

The real hard part was <actual challenge>.

That forced me to think more carefully about:
- <lesson>
- <lesson>
- <lesson>

I wrote the full breakdown here:
<link>
```

## Pattern 3: Technical breakdown

Use when the article focuses on architecture or implementation.

```txt
I wrote a technical breakdown of how I built <project>.

The article covers:
- architecture
- implementation decisions
- trade-offs
- debugging
- what I would improve next

The most interesting part was <technical insight>.

Full post:
<link>
```

## Pattern 4: AI-assisted development

Use when Codex, Cursor, Claude Code, or another coding agent is central to the article.

```txt
I used <AI tool> while building <project>.

The main lesson was that AI-assisted development works better when the project has:
- clear context
- explicit constraints
- small feedback loops
- tests
- documentation

The agent helped with <specific thing>, but the engineering decisions still came from understanding the problem.

I wrote the full article here:
<link>
```

## Pattern 5: Recruiter-facing project post

Use when the user wants the post to signal technical ability.

```txt
I published a write-up about <project>, a project where I worked on <technical areas>.

The article explains:
- what I built
- why I built it
- the architecture
- the trade-offs
- what I learned

For me, this was a practical exercise in <skill>, <skill>, and <skill>.

Full article:
<link>
```

## Pattern 6: Opinionated technical post

Use when the article has a strong thesis.

```txt
I think <technical topic> is usually discussed in a shallow way.

After building <project>, I started seeing it differently.

The important part was <specific thesis>.

In the article, I explain:
- <evidence>
- <evidence>
- <evidence>

Full breakdown:
<link>
```

## Pattern 7: Short post

Use when the user wants a concise LinkedIn post.

```txt
I wrote about <topic>.

The article covers <main subject>, but the real lesson was <lesson>.

It connects:
- <topic>
- <topic>
- <topic>

Full article:
<link>
```
