# Article Patterns

## Pattern 1: Project retrospective

Use when the user built a complete project.

Structure:

1. What I built
2. Why I built it
3. The first naive version
4. Architecture
5. Development process
6. Technical problems
7. Lessons learned
8. Next steps

## Pattern 2: From prototype to real tool

Use when the project started as a script, experiment, or MVP and became a more serious tool.

Structure:

1. The original problem
2. The quick solution
3. Why the quick solution was not enough
4. Turning it into a real tool
5. Design decisions
6. Trade-offs
7. Technical details
8. What changed after using it
9. Conclusion

## Pattern 3: AI-assisted development article

Use when the main point is how Codex, Claude Code, Cursor, or another agent helped build the project.

Structure:

1. What I wanted to build
2. How I used the AI agent
3. Where the agent helped
4. Where the agent failed or needed correction
5. How sessions shaped the architecture
6. Testing, debugging, and iteration
7. Lessons about AI-assisted software engineering
8. Conclusion

## Pattern 4: Technical opinion from project experience

Use when the user wants to argue for a technical idea based on something they built.

Structure:

1. Strong thesis
2. Context
3. Why the common assumption is incomplete
4. Evidence from the project
5. Counterarguments
6. Practical recommendation
7. Conclusion
